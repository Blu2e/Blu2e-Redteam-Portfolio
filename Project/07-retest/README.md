# OpenSSH 업데이트 후 재검증

## 실습 목적
 - 패키지 업데이트 후 SSH 서비스 버전 재확인
 - SSH 서비스가 정상적으로 접속을 처리하는지 확인
 - Ubuntu의 SSH 로그에서 실습 중 발생한 인증 기록 확인

## SSH 서비스 버전 재검증
 - 실행 명령어
  - Kali Linux에서 실행
  - nmap -sV -p 22 10.10.10.4

 - 확인 결과
  - 포트: 22/tcp
  - 서비스: ssh
  - 업데이트 후 탐지된 버전: OpenSSH 9.6p1 Ubuntu 3ubuntu13.20

 - 업데이트 전 OpenSSH 9.6p1 Ubuntu 3ubuntu13.19가 탐지
 - 업데이트 후 Nmap에서 탐지되는 서비스 버전 정보 변경 확인

## SSH 접속 검증

 - 실행 명령어
  - ssh blue@10.10.10.4

 - 접속 후 다음 명령어 실행
  - whoami
  - hostname

 - 확인 결과
  - whoami: blue
  - hostname: ubuntu-target

 - 업데이트 후에도 SSH 접속 정상 확인

## SSH 인증 로그 확인

 - 실행 명령어
  - sudo journalctl -u ssh -n 50 --no-pager | grep Accepted

 - 확인 결과
  - SSH 로그에서 다음 정보를 포함하는 인증 성공 기록 2건 확인
  - 인증 결과: Accepted password
  - 로그인 계정: blue
  - 접속 출발지 IP: 10.10.10.3
  - SSH 프로토콜: ssh2
  - 10.10.10.3은 본 실습에서 사용한 Kali Linux의 IP 주소

 - 결과 해석
  - 실습 중 Kali Linux에서 수행한 SSH 접속과 일치하는 인증 성공 기록 확인
  - 이 기록은 해당 IP에서 비밀번호 인증이 성공했다는 사실 표시. 기록만으로 실제 사용자의 신원이나 악의적인 접근 여부까지 확정할 수는 없음
  - 또한 sudo journalctl -u ssh --since "30 minutes ago" --no-pager에서는 조회 조건에 해당하는 로그가 표시되지 않았지만, 시간 범위를 제한하지 않고 최근 로그를 조회했을 때 인증 성공 기록 확인

## 재검증 결과 요약
 - 업데이트 후 Nmap에서 SSH 서비스 버전 정보 변경 확인
 - 22번 포트에서 SSH 서비스 지속 이용 가능
 - SSH 접속 후 계정과 호스트 이름 확인
 - SSH 서비스 로그에서 실습 중 수행한 비밀번호 인증 성공 기록 확인

## 검증 범위 및 한계
 - 이번 실습에서는 패키지 업데이트, 서비스 버전 변경, 정상 접속 여부 및 인증 로그 확인
 - 특정 취약점을 직접 악용하거나 공격 성공 여부를 검증한 것은 아님, 따라서 개별 취약점의 해결 여부는 공식 보안 정보와 별도의 검증 근거를 통해 판단 필요
